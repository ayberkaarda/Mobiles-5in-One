# Privacy labels: Google Play Data safety and Apple App Privacy

Status: mapping ready for review; **not submitted** (no developer accounts, ADR-0005). Every row
traces to code, configuration or an ADR. The answers describe the build on branch
`feat/inecekvar-p6` (Android release APK scanned in `docs/security/scan-reports/mobsf-static.md`,
API at migration `0005`). Re-check every row against the build that is actually uploaded.

Method (ADR-0056): start from what leaves the device (every API route the app calls, every SDK
in `package.json`, the merged Android manifest of the release APK), then follow each value into
the database models (`api/app/models/`), logs (`docs/ops/logging.md`), object storage and the
processors that receive it. Data that never leaves the device is not "collected" in either
store's sense and is listed separately in section 5.

## 5. On the device only (not collected)

Ride drafts with GPS points before upload, guest favourites, installed city packs, preferences
(`iv.lang`, `iv.theme`, selected city `iv.city`) and the native refresh token (Keychain or Keystore through
`capacitor-secure-storage-plugin`, ADR-0004). None of it is backed up (section 4).
