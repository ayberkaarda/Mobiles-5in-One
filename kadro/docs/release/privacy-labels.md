## 2. What the code does not do (and the label must say so)

- **Device location is not read.** `apps/mobile/app.config.ts` registers the `expo-location` plugin with a when-in-use permission string, but no file under `apps/mobile/src` or `apps/mobile/app` imports `expo-location` or requests the permission. Venue coordinates are venue data (typed into the venue form, `apps/mobile/src/venues/form.ts`), not user data. To verify on a built binary: the plugin adds the iOS usage string and the Android location permissions to the manifest, which store reviewers may question. Recommended before any real build: remove the plugin (owner decision, not done here) so "Location: not collected" is also true of the manifest.
- **No contacts, photos or camera access.** There is no `expo-contacts` or `expo-image-picker` in `apps/mobile/package.json`; `apps/mobile/src/profile/avatar-upload.ts` states the app has no picker yet, so the avatar upload control is not shown. The QR code is rendered, not scanned (`apps/mobile/src/teams/InviteQr.tsx`; no scanner dependency). To verify: no camera permission appears in the built manifest.
- **No in-app purchase SDK.** `react-native-purchases` is not in `apps/mobile/package.json`; no screen sells a subscription, and the device sends nothing to RevenueCat. RevenueCat only reaches the server as a webhook (`apps/web/app/api/v1/webhooks/revenuecat/route.ts`). If a purchase screen is added later, revisit sections 3 and 4.
- **No analytics, advertising or crash-reporting SDK.** No such dependency in the `package.json` of `apps/mobile`, `apps/web` or `apps/worker`. ADR-0074 (Sentry with scrubbing) is only proposed; if it is implemented, add Diagnostics rows.
- **No tracking** across other companies' apps or sites; no advertising identifier use.
- **Payments:** the app records fee shares and who has paid, but moves no money and handles no card data.
