## 1. Workflows are not at the Git repository root

What: the Git repository root is `Mobil-Package` (it holds `.git`, `.gitleaks.toml`,
`lefthook.yml`); Kadro lives in its `kadro/` subdirectory. GitHub Actions only reads
`.github/workflows/` at the repository root, so `kadro/.github/workflows/ci.yml` and
`kadro/.github/workflows/security.yml` never run.

Why: security checklist items 1, 2 and 19 need the gitleaks history scan, `pnpm audit` and the
secret grep to run in CI; today they only run locally.

Acceptance: either Kadro becomes its own repository (as the product spec assumes; both workflow
files then work unchanged, and `.gitleaks.toml` moves into it with the allow-list path
`packages/config/src/env\.test\.ts` instead of `kadro/packages/...`), or the workflows move to the
repository root with `defaults.run.working-directory: kadro` and path filters. A green run of
`Security` is linked from `docs/security/verification-matrix.md` (items 1, 2, 19).

## 2. gitleaks allow-list for build output

What: `gitleaks dir` over a built tree reports `generic-api-key` in `apps/web/.next/`
(Next.js preview and server-action keys generated by `next build`; the directory is ignored by
Git).

Acceptance: `.gitleaks.toml` gains a path allow-list for `(^|/)\.next/` (and `node_modules/`), so
`gitleaks dir --no-banner -c .gitleaks.toml kadro` is clean after `pnpm build`.

## 3. Turbo inputs for the security scripts

What: `apps/web` lints `../../scripts/security` (lint script) and its tests import
`scripts/security/*.ts`. Turbo's default inputs for `@kadro/web` do not include those files, so a
change there can be served from cache.

Acceptance: `turbo.json` adds `$TURBO_ROOT$/scripts/security/**` to the inputs of
`@kadro/web#lint` and `@kadro/web#test` (or a root task covers them).

## 4. Authorization matrix §3.1, logout row

What: the `POST auth/logout` row has one cell more than the header (an older and a newer Notes
text side by side), so Markdown renderers drop or shift the last cell.

Acceptance: one Notes cell; keep the newer text ("Revokes the presented token's family (mobile) or
session row (web); access tokens with that `sid` fail from the next request (ADR-0025).").

## 5. Optional: fixture in `packages/config/src/env.test.ts`

What: line `const badKey = '…'` uses a literal with the Stripe-style key prefix, which needs an
allow-list entry in `scripts/security/secret-grep.ts`.

Acceptance (optional): build the value at run time (for example `['s', 'k_not_a_resend_key'].join('')`);
then remove the matching `ALLOWLIST` entry (the grep fails on stale entries, so both changes go
together).
