# Mobile screens

Every route under `apps/mobile/app`, with the data it reads, its states and the `testID`s the
Maestro flows use (flow names in brackets, files in `apps/mobile/.maestro/flows`). `testID`s that no
flow uses exist for the unit tests (`apps/mobile/tests/*-screens.test.tsx`) and are listed only when
they mark a state. Endpoints are under `/api/v1`. For the structure behind these screens (guards,
query cache, error copy) see `architecture.md`.

Common states: lists use `ListQueryView` (skeleton rows, localized error with retry, cached rows
plus a notice when a refresh fails, empty state); detail screens use their own pending, error and
"not found" states with `ErrorState`; render errors fall to `QueryBoundary`. Failures are always
shown through the error catalog (`errorMessage`), never with server text.
