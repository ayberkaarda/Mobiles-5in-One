Five products, end to end.

Five independent projects in one monorepo, each built from scratch on a different stack: a mobile app, a backend API, a public SEO web and an admin area, with tests, CI, security documents and release material.

These are not live services. The web demos are static snapshots of each project's own public pages, taken from local builds with sample data (labelled [ÖRNEK]). Sign-in, forms, search and payments do not work there, and download buttons do not mean an app is published.

Projects

kadro/

Web: local build. App: Android emulator. Sample data.

Match organizer for amateur pitch football

Kadro

“Kadroyu kur, eksiği kapat, ücreti böl.”

The captain sets up the match, collects RSVPs, calls in nearby players when places are open and splits the pitch fee. No money moves in the app; the captain only tracks who has paid.

  • Expo (React Native)
  • Next.js
  • PostgreSQL + PostGIS
  • pg-boss
  • Turborepo
Status
All seven phases (0–6) merged, then a light and dark redesign. The Maestro flows have no recorded run; no store purchase was made.

askida/

Web: local build. App: Android emulator. Sample data.

Pay-it-forward network

Askıda

“İyilik askıda kalmasın.”

Donors prepay everyday items such as bread, soup or stationery at verified local shops; a person in need collects them anonymously, without an account, using a one-time code. One app runs in three modes: donor, merchant, recipient.

  • Flutter
  • Laravel
  • Filament
  • PostgreSQL + PostGIS
  • Redis
  • iyzico (fake provider locally)
Status
All seven phases merged. Real payments and attestation have not been exercised; iOS has never been built.

Web: local build. App: Android emulator. Sample data.

Digital credit ledger for small shops

Çetele

“Veresiyeyi unutma, Çetele'ye yaz.”

An offline-first credit ledger for grocers, greengrocers, butchers, barbers and tea houses. It keeps customers, debts, payments and reminders, and syncs between the owner's and the staff's devices.

  • Kotlin
  • Jetpack Compose
  • Spring Boot
  • PostgreSQL
Status
All seven phases merged, then hardening, design and a second security batch. Play Billing and Play Integrity ran against fakes and recorded fixtures; no physical device.

inecekvar/

Web: local build. App: Android emulator. Sample data.

Crowdsourced dolmuş and minibus route map

İnecek Var

“Dolmuş nereden geçer? Mahalle bilir.”

A crowdsourced map of dolmuş, minibus and shuttle lines for cities where official data is often missing. Riders plan A to B trips with transfers and download offline city packs; contributors propose lines from GPS traces and moderators review and publish them.

  • Ionic + Angular
  • Capacitor
  • Angular SSR
  • FastAPI
  • PostgreSQL + PostGIS
  • Redis
Status
All seven phases merged, then the visual redesign and its route-sign restyle. Hosting, TLS, provider accounts and iOS are not exercised.

Web: local build. App: Android emulator. Sample data.

Community platform for street animals

Patika

“Mahallenin patilerini birlikte koruyalım.”

It brings neighbourhood volunteers together: a feeding-station map, “Fed” check-ins, animal profiles, adoption listings, urgent-help posts and a nearby vet directory. Volunteer locations are never stored.

  • .NET 10 MAUI (Android)
  • ASP.NET Core
  • Razor Pages
  • PostgreSQL + PostGIS

How it was built

All five projects followed the same path. Every number here comes from a file in the repository.

Seven phases, all merged

From the foundation (phase 0) to hardening and release readiness (phase 6); all seven phases are merged into main for every project.

23

Items in the security matrix

Each project grades the same checklist in its own verification matrix; a “partial” row names the missing proof.

5 / 5

Attack report, ZAP and MobSF scans

Every project has an attacker-view test report, a ZAP scan and a MobSF scan; the reports are in each project's docs/security folder.

15

GitHub Actions workflows

Per project a CI and a restore-drill workflow, a separate security workflow for four of them (Patika's scans live in its CI), and a manual mobile e2e for Kadro. Secret scanning with gitleaks.

212

Architecture decision records

Decisions from stack and versions to design direction, kept as numbered files in each project's docs/adr folder.

0

Stores or production hosts

Payments, store billing and third-party providers run against fakes or sandboxes; every README says which parts are real and which are simulated.
