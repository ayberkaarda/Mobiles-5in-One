# Environment variables

Server configuration comes from the process environment. For local work, `cetele/.env.example`
(committed, dummies only) is copied to `cetele/.env` (gitignored) and read by `docker-compose.yml`.
`application.yml` uses `${VAR}` placeholders only, and there is no `application-prod.yml` in the
repository.

The Android app has one build-time key, `cetele.apiBaseUrl`, read from `android/local.properties`.
No other value is compiled into the app.

This file was reconciled in Phase 2 with `cetele/.env.example` and `cetele/docker-compose.yml`. The "Bound in" column says which phase first reads the
key in code. A key declared in `.env.example` but bound in a later phase is documented now so that
the names are stable; until its phase it has no effect. If this file and `.env.example` disagree,
`.env.example` and the compose file are the source of truth and this file is fixed.

## Conventions

- `.env.example` holds an empty value or a documented dummy that is valid only locally. It never
  contains `TODO`, `FIXME`, `lorem` or `YOUR_` text and no value shaped like a real key or token.
- "Secret in production" means the value must come from the host environment or a secret store and
  must never appear in the repository, an image layer or a log.
- Local values match `docker-compose.yml` (project `cetele`, host ports in the 60xxx block, bound to
  `127.0.0.1`). The compose file is the source of truth for ports and service names.
- Code reads configuration through typed properties bound from `application.yml`; it never reads the
  environment directly.

## Local stack

| Service    | Host port                                                                          | Notes                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `postgres` | 60432 (to 5432), key `CETELE_PG_PORT`                                              | PostgreSQL 16.15; database `cetele`; the init SQL in `docker/postgres/init` also creates `cetele_test`. |
| `minio`    | 60900 (API, `CETELE_MINIO_API_PORT`), 60901 (console, `CETELE_MINIO_CONSOLE_PORT`) | Local stand-in for Cloudflare R2; private bucket `cetele-media`.                                        |
| `mailpit`  | 60025 (SMTP, `CETELE_MAILPIT_SMTP_PORT`), 60825 (web UI, `CETELE_MAILPIT_UI_PORT`) | Optional; catches alert mail in Phase 4 and Phase 6.                                                    |
| `server`   | 60080 (to 8080), key `CETELE_SERVER_PORT`                                          | Image `cetele-server:local`; health at `/actuator/health`.                                              |

Every host port is read from the key named in the table, with the value shown as the default
(`${CETELE_PG_PORT:-60432}` and so on in `docker-compose.yml`), so a second stack can run side by
side. The compose project name stays `cetele`. The server container runs profile `local` by default,
with `CETELE_SMS_PROVIDER=fake` and `CETELE_INTEGRITY_MODE=fake`.

The Android emulator reaches the server at `http://10.0.2.2:60080`.

## Server keys

Values are those of `cetele/.env.example`. Compose passes the runtime, database, storage and
auth keys (pepper, JWT keys, OTP local echo, SMS provider, integrity mode, Play package
name, trusted proxies) and the Phase 2 keys (public base URL, Netgsm keys, SMS daily cap, jobs switch) to the `server` container, with the same dummies as defaults
(`${VAR:-default}`), so `docker compose up -d --wait` works without a `.env` file. The other keys are
declared in `.env.example` for stable names and are read by no code yet.

Notes:

1. Spec item 5 requires an integrity token on `otp/request` in Phase 1. It is verified through an
   interface with a fake verifier that is allowed only in `local` and `test`;
   `CETELE_INTEGRITY_MODE` and `CETELE_PLAY_PACKAGE_NAME` are therefore bound in Phase 1, while the
   Google client and `CETELE_PLAY_SERVICE_ACCOUNT_JSON` stay in Phase 4
   ([ADR-0006](../adr/0006-integrity-verifier-and-local-adapters.md)).
2. `CETELE_SMS_PROVIDER=fake` is bound in Phase 1 (OTP delivery through `SmsGateway`) and
   `netgsm` in Phase 2. A profile other than `local` or `test` can therefore start with
   `CETELE_SMS_PROVIDER=netgsm` and the three Netgsm credentials; with `fake` or an empty value it
   still refuses to start. The Netgsm request shape is not verified against the live API and no
   real SMS was sent (`not exercised: no provider account`).
3. Production must set `CETELE_TRUSTED_PROXIES`, `CETELE_OTP_PEPPER` and both JWT keys, and must
   leave `CETELE_OTP_LOCAL_ECHO` off. The keys `CETELE_OTP_PEPPER` and `CETELE_JWT_ES256_*` are
   created per environment and never committed.
4. The server reads `CETELE_OTP_PEPPER`, `CETELE_OTP_LOCAL_ECHO`, `CETELE_INTEGRITY_MODE` and
   `CETELE_PLAY_PACKAGE_NAME` through Spring's property mapping (`cetele.otp.pepper`,
   `cetele.otp.local-echo`, `cetele.integrity.mode`, `cetele.play.package-name`), so `application.yml` has no entry for them; the defaults are those in
   the table.
5. Compose does not build the server image. After a code change run `./gradlew jibDockerBuild` in
   `cetele/server` before `docker compose up -d --wait`, otherwise `cetele-server:local` is the
   previously built image.
6. Production needs `CETELE_PUBLIC_BASE_URL` (the server does not start without it), the storage
   endpoint and credentials (mandatory since Phase 2) and, for reminders, `CETELE_SMS_PROVIDER=netgsm`
   with its credentials.

## Android key

| Key                 | File                       | Purpose                                                    | Behaviour                                                                              |
| ------------------- | -------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `cetele.apiBaseUrl` | `android/local.properties` | Base URL of the API, exposed as `BuildConfig.API_BASE_URL` | Debug builds fall back to `http://10.0.2.2:60080` when missing; a release build fails. |

`local.properties`, `keystore.properties` and `*.jks` are gitignored and never committed. The app
ships no secrets: the SQLCipher key is created on the device (spec item 1).
