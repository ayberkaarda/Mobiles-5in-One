# Play Data Safety mapping — draft

Repository snapshot: 2026-10-11. No Play Console account exists. This is a code-based inventory for a future form, not a submitted declaration. It extends [aso.md](../seo/aso.md); [ADR-0004](../adr/0004-portfolio-delivery-scope.md) limits all live-provider claims. No runtime traffic inspection was performed for this document.

## Reading the mapping

“Collected” below means data leaves the phone for the server or a configured provider, including owner-entered customer records. Local-only processing is identified separately. Required means required for the named feature, not that every user must use that feature. Category labels are proposed form mappings, subject to Console review.

Transfers to the SMS provider, Google, hosting and object storage are described even where a service-provider exception may apply to the form's “shared” answer. WhatsApp, exported files and statement links are user-requested disclosures. Do not turn these distinctions into an unconditional “no transfers” answer. Local adapters send no real SMS and return fixture Play results.

Paths below are relative to `cetele/`. Prefixes expand to these actual source directories:

- `S/` = `server/src/main/kotlin/app/cetele/server/`
- `D/` = `android/core/data/src/main/kotlin/app/cetele/android/core/data/`
- `N/` = `android/core/network/src/main/kotlin/app/cetele/android/core/network/`
- `F/<module>/` = `android/feature/<module>/src/main/kotlin/app/cetele/android/feature/<module>/`

Transport code **T**: release app requires HTTPS in `android/app/build.gradle.kts`; `android/app/src/main/AndroidManifest.xml` prohibits cleartext, and `N/pinning/PinnedEngineFactory.kt` pins the API host. `S/config/TransportSecurityProperties.kt` and `S/config/LocalOnlyAdapterGuard.kt` require secure incoming requests outside local/test. Debug and local storage use HTTP. Provider, storage, database and reverse-proxy hops need deployment checks; **T is a release design, not proof of end-to-end deployed encryption**. In particular, storage endpoint configuration alone does not require HTTPS (`S/config/StorageProperties.kt`).

At-rest code **R**: `D/database/CeteleDatabaseFactory.kt` opens Room through SQLCipher; `D/vault/KeystoreVault.kt` seals vault values with AES-256-GCM and an Android Keystore key. Server PostgreSQL field mappings do not encrypt ordinary rows; disk/storage encryption and backup encryption cannot be confirmed. Hashing a credential is not encryption of its accompanying phone or IDs.

Deletion **A**: renewed SMS-code authentication starts in-app account deletion (`F/settings/account/AccountDeletionViewModel.kt`, `S/account/AccountService.kt`). A 14-day grace precedes the hourly executor. **H**: an owner requests shop deletion with renewed authentication; `S/account/deletion/DeletionExecutor.kt` removes storage prefixes, then shop rows. Storage failure retries; changed membership can block completion. Account deletion removes owned shops only under the applicable ownership/explicit-choice rules; transferred or other owners' shops remain.

## What is not collected

- No GPS, coarse/fine location sensor access or location permission is present in the app manifest or reviewed source. Province/district are entered shop information. IP processing and location visible in a user-supplied photo or note still need category review; this is not a claim that records cannot contain a place.
- No address-book access or contacts permission is present. Customer and invitation phones are entered by users. They are still collected personal information when synced.
- No advertising ID permission, advertising-ID reader or ad SDK integration was found in app source/build declarations. Installation UUID is collected and must not be confused with an advertising ID.
- No device SMS-inbox reader, audio recording, health-data feature, bank-account or card-entry flow was found. Outgoing provider SMS is covered above. No analytics or Sentry client integration was found; `SENTRY_DSN` is declared in environment documentation but is not bound in current server code. Masked server logs still exist.

Scope evidence: `android/app/src/main/AndroidManifest.xml`, feature source trees, `android/app/build.gradle.kts`, module build declarations, server source and `server/src/main/resources/application.yml`. A final merged release manifest and transitive SDK behavior were not inspected in a built artifact.

## Retention and deletion limits

`S/account/retention/RetentionSweeper.kt` deletes OTP rows older than one day, refresh rows more than 30 days past expiry/revocation, invitations more than seven days past expiry, links more than 90 days past expiry/revocation, and failed/expired media rows older than seven days. Jobs depend on `CETELE_JOBS_ENABLED`. Active customer/ledger history has no general automatic expiry in the reviewed code.

`D/session/SessionManager.kt` wipes Room, encrypted photos and vault values on sign-out; settings retain the installation UUID and theme. Server completion cannot prove an offline or unused phone executed cleanup. Temporary exports, camera caches, WorkManager input, recipient files, provider records, storage object versions and pre-deletion backups need separate checks. `/hesap-silme` is currently explanatory Markdown rendered by the public site, not a web deletion request form.

## Differences to check before submission

1. Complete the actual Console taxonomy and sharing-exception review, especially customer data, province/district, outgoing SMS, IP/security data and Google SDK behavior. No Console account or current form is available in this repository.
2. Confirm HTTPS on every release hop: API/proxy, presigned upload/download, server-to-storage, database, SMS, Google and any log/mail sink. API certificate pins do not cover arbitrary presigned storage hosts. No live TLS or provider traffic was exercised.
3. Confirm server database, object storage, backups and provider-held data encryption at rest and selected hosting region. Android SQLCipher alone cannot support a blanket at-rest claim.
4. Review raw purchase tokens in WorkManager, unencrypted UUID/settings and temporary camera/export files. Confirm cleanup after cancellation, sign-out, process interruption and account deletion; WorkManager cancellation alone does not demonstrate erasure.
5. Review retention of deletion-request user/shop UUIDs, orphan subscription hashes/history, pending webhook tokens, diagnostics and provider message IDs. Source disagrees with any interpretation that all identifiers disappear at deletion.
6. Confirm how customer erasure requests remove old sync payloads and immutable ledger history. A customer tombstone is not hard deletion. Account deletion after transferring ownership does not erase the continuing shop's records.
7. Replace sample privacy/KVKK texts with reviewed, deployment-specific texts and a real controller/support contact. Provide a public deletion-request mechanism; the current explanatory page does not receive requests. Confirm provider logs, backups and object versions honor the chosen retention/deletion process.
8. Capture release network behavior and inspect the final merged manifest/dependency inventory for new SDK data. Live Play Billing, Integrity, SMS and store declarations are `not exercised: no corresponding provider or Play Console accounts`.

These checks refine the existing ASO draft rather than treating its intended release settings as observed deployment facts.
